## 1. Existing fully-local autonomous coding pipelines

**What 30B-class local models actually achieve on real multi-file tasks:**

- **Qwen3-Coder-30B-A3B scores 50.3% on SWE-bench Verified** — and notably, a fine-tune of the general Qwen3-30B-A3B-Instruct matches it at the same 50.3% pass@1. This is the realistic ceiling for your model class with a good scaffold ([Pinggy roundup](https://pinggy.io/blog/best_open_source_self_hosted_llms_for_coding/), [Qwen3-Coder repo](https://github.com/QwenLM/Qwen3-Coder)). Caveat for you: that's the *Coder* variant or a SWE-fine-tune; stock Qwen3-30B-A3B (your reasoning model) will land meaningfully lower on repo-level tasks.
- **Devstral-Small (24B) + OpenHands: 46.8% SWE-bench Verified** (234/500 resolved), beating DeepSeek-V3-0324 and Qwen3-235B-A22B *under the same scaffold*. Mistral and All Hands explicitly built the model around the scaffold — the lesson is that model+harness co-design beats raw parameter count ([OpenHands blog](https://openhands.dev/blog/devstral-a-new-state-of-the-art-open-model-for-coding-agents), [Devstral paper](https://arxiv.org/html/2509.25193v1), [SWE-bench experiments PR](https://github.com/SWE-bench/experiments/pull/228)).
- **The harness matters as much as the model:** on Terminal-Bench 2.0 the *same model* swings 30–50 percentage points depending on which harness wraps it ([MindStudio analysis](https://www.mindstudio.ai/blog/best-open-source-llms-agentic-coding-2026)).
- **Aider with local Qwen3-32B: 45.8% on aider polyglot in "whole" edit format with 100% well-formed responses, but only 41.3% in "diff" format with 94.2% well-formed** (17 errors, 14 malformed). Via OpenRouter with default thinking it dropped to 40.0% with 119 error outputs and 12 context exhaustions. Edit-format adherence is a first-order failure mode for sub-70B models; whole-file rewrites are more reliable than diffs ([aider Qwen3 benchmark](https://aider.chat/2025/05/08/qwen3.html), [aider leaderboards](https://aider.chat/docs/leaderboards/)).
- **gpt-engineer / Devika with local models:** essentially no quantitative success data exists. gpt-engineer's own docs frame local models as "catching up" with degradation from quantization; Devika recommends Claude 3 "for optimal performance" and publishes no local-model numbers. An empirical failure study found open models show the same failure classes as closed ones *plus extra parsing breakdowns* ([gpt-engineer open models doc](https://gpt-engineer.readthedocs.io/en/latest/open_models.html), [Devika repo](https://github.com/stitionai/devika), [failure study](https://arxiv.org/pdf/2601.13655)).
- **smolagents (HuggingFace):** their CodeAgent design (agent writes actions as Python code, not JSON tool calls) uses ~30% fewer steps/LLM calls and scores higher on hard benchmarks; open models matched proprietary ones on their GAIA-derived suite ([smolagents blog](https://huggingface.co/blog/smolagents), [structured CodeAgent blog](https://huggingface.co/blog/structured-codeagent), [beating GAIA](https://huggingface.co/blog/beating-gaia)).

## 2. TDD-loop agents and execution feedback

- **Tests-in-prompt measurably helps:** Mathews &amp; Nagappan, "Test-Driven Development for Code Generation" ([arXiv 2402.13521](https://arxiv.org/abs/2402.13521)) — giving GPT-4 the tests alongside the problem statement: MBPP 69.67% → 82.45% (+12.8 pts), HumanEval 78.66% → 87.81% (+9.2 pts), CodeChef 23.0% → 26.1%. Effect replicated on Llama 3. Writing/locking tests *before* implementation is empirically the right ordering, not just discipline.
- **Execution feedback beats single-shot, especially via iteration:** "How Many Tries Does It Take? Iterative Self-Repair Across Model Scales" ([arXiv 2604.10508](https://arxiv.org/html/2604.10508)) tested Llama 3.1 8B, Qwen3 32B, Llama 3.3 70B, and others with up to 5 repair attempts fed execution errors: **+4.9 to +17.1 pts on HumanEval, +16.0 to +30.0 pts on MBPP — gains universal across scales, and current instruction-tuned small models no longer need fine-tuning to self-repair. Most gains concentrate in the first two repair rounds.** This is the strongest direct evidence that your RED-GREEN loop with pytest as verifier is the correct architecture for a 30B model, and that a repair cap of 2–3 rounds captures most of the value.
- The lineage: Self-Debugging ([arXiv 2304.05128](https://arxiv.org/pdf/2304.05128)) established unit-test execution feedback as the strongest feedback signal; a test-execution agent providing feedback reached 89.9% on MBPP in a multi-agent setup ([survey, arXiv 2408.02479](https://arxiv.org/pdf/2408.02479)).
- **Counterpoint to watch:** "Rethinking the Value of Agent-Generated Tests" ([arXiv 2602.07900](https://arxiv.org/html/2602.07900v2)) finds that when the *agent writes its own tests mid-task*, test-writing intensity only weakly correlates with task success, and agents drift to print-based observation over assertions. Implication: the value is in tests generated in a *dedicated, gated phase* and then frozen as the verifier — exactly your deterministic-gate design — not in letting the agent freestyle tests during implementation.
- A TDD benchmark now exists: "Tests as Prompt" ([arXiv 2505.09027](https://arxiv.org/html/2505.09027v1)) if you want an eval target.

## 3. Self-consistency / multi-sample voting for agent steps

- **For final code artifacts: clearly worth it, if you vote with execution.** CodeT ([arXiv 2207.10397](https://arxiv.org/abs/2207.10397)) — sample N solutions + N generated tests, score by dual execution agreement: HumanEval pass@1 47.0% → 65.8% (+18.8 absolute) on code-davinci-002, consistent gains across five models including small ones. Functional Majority Voting (clustering candidates by runtime execution signatures) shows similar boosts ([Majority Voting for Code Generation](https://arxiv.org/html/2604.15618)). Agentless itself samples multiple candidate patches and selects via regression tests ([arXiv 2407.01489](https://arxiv.org/abs/2407.01489)).
- **For intermediate agent steps: mostly not worth it.** Sophisticated selection methods often fail to beat plain self-consistency once inference cost is counted, and LLM-as-judge selection (Universal Self-Consistency) adds ~10% inference time and ~15% memory for marginal gain ([Latent Self-Consistency](https://arxiv.org/pdf/2508.18395), [Self-Certainty best-of-N](https://arxiv.org/pdf/2502.18581)). Plain textual majority voting also doesn't apply cleanly to free-form agent actions (no canonical answer to vote on).
- **Practical rule for single-stream local inference (your MLX setup, where N samples = N× wall-clock):** spend samples only where a cheap deterministic verifier exists (does the patch apply? do tests pass? does JSON validate?) — i.e., best-of-N with execution filtering at the patch level — and run all other steps greedily. Voting on *enum-output* steps (classify/triage with Gemma) is cheap and reasonable; voting on reasoning steps is not.

## 4. Pipeline-of-small-steps vs monolithic agent

- **Agentless ([arXiv 2407.01489](https://arxiv.org/abs/2407.01489))** is the canonical result: a fixed three-phase pipeline (hierarchical localization → repair with multiple candidate diffs → test-based patch validation), no agent autonomy, no tool choice — beat every open-source *agent* on SWE-bench Lite at the time (32.0%) at $0.70/issue. OpenAI adopted it as their reference scaffold for GPT-4o and o1. The weaker the model, the stronger the argument for taking action-selection away from it.
- **Decomposed prompting beats monolithic prompts broadly:** gains of +4.2 to +12.9 pts on math/multi-hop benchmarks; decomposed 50.6% vs CoT 36% EM in one comparison ([EmergentMind survey of prompted decomposition](https://www.emergentmind.com/topics/llm-based-prompted-decomposition)).
- **"Can Small Agent Collaboration Beat a Single Big LLM?" ([arXiv 2601.11327](https://arxiv.org/html/2601.11327v1))**, Qwen3 4B–32B on GAIA: a 4B model *with tools* (18.2%) beat a 32B model *without* (12.7%); tool augmentation gave the largest, most consistent gains for small models. Critical finding for you: **full "thinking" mode frequently *degraded* agentic performance** — causing tool omission, looping/non-termination, and format drift (4B agentic accuracy fell 13.3% → 9.1% with thinking on). Best results came from thinking applied *only to the planning role*, not uniformly.
- smolagents' 30% step reduction from code-actions and the aider diff-format data above reinforce the same theme: every degree of freedom you remove from a sub-70B model (output format, action space, phase ordering) converts directly into reliability.
