**4. **5. Over-correction risk.** Low, and this is the right home for the shared rules. One item is care-performance: line 25 "Follow the repo's existing style (detected by datum-awake)" tells the model nothing actionable and invites it to narrate style-matching.

**6. Length and structure.** 1342 bytes for ~20 rules — high density, justified. No output contract (correct: it is a header, not a task).

**7. Recommendation. KEEP** (with two one-line edits). It is the only correctly-placed stable prefix in the batch and should absorb more, not less. Drop or repoint line 29 (dead link), and soften line 12 to "500 lines is a review trigger — split only on a real seam" so it stops manufacturing splits. ## Ordering of shared preamble vs template

The preamble is prepended correctly (`shared/prompts.ts:23`, always first, no slots) — that part of the design is right. Three problems around it:

1. **Coverage is partial and undocumented.** Only the eight helpers in `shared/prompts.ts` prepend it. `datum-awake.ts` (2 calls) and `datum-closeout.ts` (1 call) render raw, so the CLI rule, the coding rules and the test conventions never reach the scan, distill or synthesis agents — while `awake-distill.md:10` tells the model it goes on "every agent prompt."

### Ordering of shared preamble vs template

The split is clean and worth naming: **`red.md`, `red-retry.md` and `refactor-check.md` get `PREAMBLE` first, then the template, then an appended witness/schema block** — the preamble is the ideal cache prefix and it is already in the right place. **The five Plan/Properties templates get no preamble and no agentType**: `renderPrompt(template, …)` is the entire prompt, plus an append. So the two halves of the pipeline have opposite problems. Act prompts: good prefix, but the template's own stable rules sit *after* its slots (2% cacheable in `red.md`), and the appended contract lands after a template line that already claimed to be the contract. Plan prompts: no stable prefix at all beyond ~100 B, no tools contract, no `maxTurns`, no hooks — a `decompose-tasks` call on opus re-pays 8.9 KB of rules every time and runs under whatever default agent the harness supplies.

Across all eight slot-bearing templates the pattern is identical and mechanical: **role line → variable inputs → stable rules → schema**. Inverting the middle two — role → stable rules → schema → variable inputs — is wording-preserving in six of eight (the exceptions are `properties-derive.md`, where line 35's "above" becomes "below", and `plan-decompose.md`, where lines 21-23 must travel with `{{contextFilesSection}}`), and no test in `skills/src/*.test.ts` anchors on position; every pin in this batch is an unanchored substring or regex over a whole-file read.

### Three highest-value changes, ranked by what breaks a run

1. **Give `refactor-check` an agent definition it can execute under.** `stageOpts('reader')` → `agents/datum-reader.md`: *"You read one file and return its contents as structured JSON"*, `tools: Read`, `maxTurns: 4`. The prompt asks it to read `[...implFiles, ...testFiles]` and return a quality judgement against eight criteria. A gate that FLOW.md §5 already lists as unverified should at least be provisioned to answer; today its most likely outcome is `refactor_check_no_result` (`datum-tdd-act-lane.ts:1509`), which silently skips REFACTOR — a `should_refactor` false negative that no later check catches, because REFACTOR is the only stage that removes tells. Fix: a dedicated `datum-quality-reader` definition (`tools: Read, Grep`, `maxTurns: 12`), or drop the agentType for this one call.

2. **Resolve the RED commit-procedure conflict in `agents/datum-red.md`.** The definition's step 6 (`git add . && git commit -m "<commit_prefix>: <description>"`) contradicts both stage templates and is exactly the shape `datum-tdd-act-lane.test.ts:253` forbids in prompts. **Duplication that should live once.**

1. **The lens content is restated in the shared system prompt.** `agents/datum-skeptic.md` tells *every* lens: "1. Look for edge cases the tests missed … 3. Look for off-by-one errors, empty collection handling, None/null paths … 4. Look for state mutations that violate invariants." Those three clauses are `skeptic-edge.md` and `skeptic-error.md` restated. A system prompt that hands all three lenses the same checklist inflates agreement, so the 2-of-3 rule promotes more findings than three genuinely independent lenses would, at three model calls per lane. The lens-specific lines belong only in the lens templates; the definition should keep the stance, the evidence requirement and the exclusion list.

2. **The evidence rule is stated three times in one prompt.** `agents/datum-skeptic.md` — "EVIDENCE REQUIREMENT: No evidence = no finding … LLM reasoning alone is not evidence (Huang et al. 2023)"; `skeptic-base.md` — "Only report bugs you can demonstrate with evidence. 'This might be a problem' is not a bug"; and each lens's "For each finding:" clause. Once, in the definition, is enough.

3. **The output shape is stated four ways.** `SKEPTIC_SCHEMA` (`{description, evidence, severity}`), the definition ("bugs_found (array of {description, evidence, severity})"), `skeptic-base.md` (same three, as a bulleted list), and each lens's own two-or-three-field phrasing that names none of them. **Ordering of shared preamble vs template.** The composed skeptic prompt is `agent-preamble.md` → `---` → `skeptic-base.md` (first slot `{{wt}}`, line 3 of 30) → `contextWitnessInstruction` → lens.
