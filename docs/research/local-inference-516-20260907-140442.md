# Local inference for datum stage agents (#516, #515) — measured plan

run_id: 20260907-140442 · audit_dir: `.temp/local-516/` (38 request/response pairs, `requests.jsonl` index, `props-qwen38.json`) · endpoint: llama.cpp b10448 behind llama-swap at `http://192.168.0.211:8080/v1` · probes: 38 sequential chat completions plus one deliberate concurrent pair · metric: wall-clock, not cost.

## 0. Load-bearing findings

1. The endpoint as observed differs from #516 in four ways: qwen38 runs with `-c 67584` (not 262144), `--reasoning-budget 4096 --reasoning-effort low` pinned server-side, `-ctk q4_0 -ctv q4_0` quantised KV, and `--slot-save-path /opt/kv-cache`; and qwen38 and qwopus9b were **co-resident** (`/running` listed both `ready`) for the whole qwopus9b batch, so a per-stage split between them cost no swap. The first request of the session did pay a swap (25.7 s wall) because another session had loaded a third alias, `qwen`.
2. Byte-identical repeats and conversation continuations hit the KV cache reliably: 411/415, 498/502, 873/877 cached on repeats; 776/810 and 843/901 on tool-loop continuations, on both models. A different prefix in between did **not** evict the original (411/415 again afterwards). #516's "a different-prefix request evicts" is not what this build does.
3. Partial-prefix reuse (same preamble, different tail) is unreliable: 390, 390, 870, 19, 19, 233 cached tokens against a shared 411-token preamble in six samples. Design for byte-identical prompts and continuations, not for "the preamble is cached whatever follows".
4. `reasoning_effort` on qwen38 is rendered by the chat template as a sentence **prepended to the system message**, so every distinct effort value is a distinct prefix (prompt grew 426 → 450 → 462 tokens for none/low/high, cache fell to 0 on each change). One effort value per model per run, or the preamble cache is lost on every alternation.
5. `response_format: json_schema` (strict) works 3/3 on both models, `json_object` 1/1 on both, and a forced `submit_answer` tool 3/3 on both. The grammar path decodes ~25% slower on qwen38 (26 vs 36 tok/s). Both paths drop optional fields (`files_written`, `read_witness`, `test_exit_code` were omitted in several answers): anything the runner asserts on must be in `required`.
6. Native tool calling works on both models: `finish_reason: "tool_calls"`, `tool_calls[].function.arguments` as a JSON string, 32-char random ids, two turns each. The empty-content-after-tool-result quirk did not reproduce (0/2 with thinking off); the interposed assistant turn is harmless.
7. Thinking on qwopus9b with a short `max_tokens` returns empty content: 120-token cap gave `finish_reason: length`, 369 reasoning chars, no content. `chat_template_kwargs.enable_thinking=false` fixes it (159 tokens, 2.0 s). On qwen38, `reasoning_effort: none` produced zero reasoning; `low` cost +128 tokens/+4.5 s and `high` +289 tokens/+9.9 s on a trivial task with identical code out.
8. Speed: qwen38 prefill 530–570 tok/s uncached, decode 30–38 tok/s (24 at 22k context); qwopus9b prefill 970–1330 tok/s, decode 100–108 tok/s (71 under a json_schema grammar). A 21k-token uncached prompt cost 40 s of prefill on qwen38. Every uncached kilotoken is ~1.9 s on qwen38 and ~0.9 s on qwopus9b.
9. Concurrency: of two simultaneous requests the first returned in 2.0 s and the second **never returned** within the 300 s client timeout, with no HTTP error and `requests_deferred 0` afterwards (one sample). The client cap of 1 is not an optimisation; without it a lane hangs until its own timeout.
10. Nothing in this repo reads the `runtime` block of `.datum/config.json` (base_url, models, max_concurrency), and `datum/agent_loop.py` has no production caller (tests only). The "current local path" is not wired to the pipeline; whatever consumes `runtime` is host-side and unverified.

## 3. Call inventory — what can move to the local endpoint, and by which mechanism

Today every LLM call in the pipeline is `agent(prompt, opts)` inside a Workflow script running in the host's sandbox, dispatched as a Claude Code subagent chosen by `stageOpts(kind)` from `agents/datum-*.md`. The sandbox has no filesystem or shell (FLOW.md §5 closures on relays), so a script cannot open a socket to llama.cpp itself; the only ways a call reaches the local endpoint are:

- **Mechanism A — bridge step.** The stage becomes a deterministic batch step: a hosted `datum-cli` runner executes `datum local-stage <kind> --packet <file> --out <file>` and the script reads the result file's receipt (path, bytes, sha), exactly like the lane-spec export today. datum's own Python loop calls the endpoint with native tool calls, tools executed in-process under `command_guard`, and emits the stage schema via `submit_answer`. Cost per stage: one hosted Haiku runner call as transport (~30k hosted tokens, no wall-clock of note) and the Bash tool's 600 s ceiling on the whole local stage (`BATCH_TOOL_TIMEOUT_MS`).
- **Mechanism B — host routing.** The host's OpenAI-compatible workflow mode, the apparent consumer of the `runtime` block in `.datum/config.json` (no reader in this repo; the block still points at the retired oMLX port 12201 and `OMLX_API_KEY`). If the host honours it, every `agent()` call goes local including the datum-cli runners, and `agent_types` must be false (agent-types.ts: that runtime has no agentType support), which also disables the PreToolUse hooks and puts `deterministicChecks()` back to the LLM ownership checks. **Unverified** end to end; not recommended as the first path because it moves the batch runners too (item 4 below).

## 5. Concurrency design

- **Client cap of 1 per server process**, enforced where the requests originate: `datum local-stage` takes an exclusive `flock` on `.datum/local/<model>.lock` around each HTTP request (lanes run in separate runner processes, so an in-process semaphore is not enough). Two locks, one per model, allow qwen38 and qwopus9b to serve one request each concurrently; whether co-resident decode contends badly (#516 says ~4x) is **unverified** here and is a benchmark question, with a single global lock as the fallback switch (`local.max_concurrency: 1`).
- **Queueing, not erroring.** A lock wait is normal; it is logged with the wait time per call so the benchmark can attribute wall-clock to queueing vs inference. A hung request (E6) is bounded by a socket timeout: 60 s connect, `max(120, prompt_tokens / 400 + max_tokens / 25 + 30)` s read, named `local_request_timeout`, one retry only if the worktree guard says nothing was written (the existing `resilientAgent` dirty guard already covers the batch side).
- **Act's five lanes stay five.** Lane orchestration, worktrees, and the hosted batch verifiers (test suites, count gates, ownership diffs) run in parallel as they do now; only the inference requests serialize behind the lock. That overlaps lane A's test run with lane B's GREEN decode, which is the only parallelism a single slot can give. Do not reduce the batch size to 1: that would serialize the test runs too.
- **Ordering within the queue.** FIFO. A "prefer the same stage kind as the last request" priority would raise prefix hits (finding 3) but is an optimisation to measure, not to build first. The cheap version is already free: a lane's RED tool-loop turns are consecutive continuations of one conversation, and the lock is held per request, not per stage, so other lanes interleave between turns; measure the hit rate before deciding whether to hold the lock for a whole stage.
- **Bash tool ceiling.** A local stage under mechanism A cannot exceed 600 s of runner time. Budget: `max_steps` × (prefill + decode) must fit; at qwen38 speeds that is ~12 tool turns of ~3k tokens with 800-token outputs, so `max_steps` defaults to 10 for writers and the stage names `local_stage_budget_exhausted` when it runs out, so the lane fails by name instead of `batch_timeout`.
- **Swap logging.** Before every request `GET /running` (llama-swap) is recorded; a request to a model not in the list logs `local_model_swap: <model> (first-request wall <s>)`. Zero swaps per run is a benchmark acceptance criterion.

## 6. Prompt-shape recommendations

- **Byte-stable prefix per (model, stage kind).** The prefix is: the server's reasoning sentence (chosen by the request's effort value, so fix it per model) + `agent-preamble.md` + `---` + the template's rules block up to the first `{{slot}}`. A test hashes the rendered prefix for two lanes of the same kind and asserts equality (extends `prompts-audit.test.ts`'s 55% rule). Tools definitions are rendered into the system message after the content, so a stage kind's tool list must also be constant.
- **System vs user placement.** Keep the preamble + rules in the system message and everything variable (packet, spec, tool results) in user/tool turns; a change inside the system message zeroed the cache in 3/3 samples while user-side changes kept partial hits in 4/7. Never append per-call text to the system message.
- **Schema placement.** Do not paste the schema into the prompt; carry it as the `submit_answer` tool's `parameters` (constant bytes, part of the prefix). Put every field a runner reads into `required`: STAGE_RESULT_SCHEMA gains `files_written`, `test_exit_code`, `read_witness` (and `status`, `needs_write`, `reason` for GREEN) in the local profile; REFLECT and SKEPTIC gain `read_witness`.
- **Context budgets per call** (tokens, measured at ~1.9 s per uncached kilotoken on qwen38): judges 6k prompt / 400 output; writers 12k prompt / 1500 output; review lenses 16k prompt (diff capped and chunked by file); tool results truncated to 4k chars head+tail (`_truncate_tool_output` already does this); a call over budget is `local_prompt_over_budget`, never silently truncated. `CONTEXT_RELAY_BUDGET_BYTES` (16 KiB ≈ 4k tokens) already fits.
- **Reasoning.** qwen38: `reasoning_effort: "none"` for every judge, `"low"` for writers, never `high`; qwopus9b: `chat_template_kwargs: {enable_thinking: false}` everywhere, and if thinking is ever enabled the floor is `max_tokens ≥ 512` (E4: 120 returned nothing).
- **Sampling.** Send temperature 0.2 for judges, 0.6 with the server's top_k 20 / top_p 0.95 for writers (the server does not read generation_config; `THINK_SAMPLING` in agent_loop.py was tuned for the oMLX Qwen build and should be replaced by the launch flags' values).
- **Messages, not prompt strings.** Retire the REASONING/FILE/NEXT text protocol and the think+decide double call in `agent_loop.py`: it costs two requests per step on a single slot and defeats continuation caching; use native `tool_calls` and keep the assistant `tool_calls` message verbatim in history so the next turn is a byte-exact continuation (776/810 cached).

## 8. Revised task list for #516 (each with a measurable acceptance criterion)

1. **Endpoint client.** `datum/local_llm.py`: `local.base_url` default `http://192.168.0.211:8080/v1`, `api_key` `local`, per-model table, connect timeout 60 s, read timeout by formula (§5), retries only on 429/503/connection-refused with a 3-attempt cap; `GET /running` recorded before each request. AC: `datum local-probe` prints the resident list and one round-trip with `cached_tokens` and `timings`; a fake-server unit test proves a hung socket raises `local_request_timeout` within read-timeout + 1 s and that a 500 is not retried.
2. **Concurrency cap.** `flock` per model under `.datum/local/`, `local.max_concurrency` (1 = one global lock, 2 = one per model). AC: two `datum local-stage` processes against a fake server that sleeps 2 s finish with the second's request start ≥ the first's response end; the wait is in each call's log line.
3. **Stage bridge (mechanism A).** `datum local-stage <kind> --packet <path> --out <path>` runs the native tool loop and writes the schema JSON; the lane script dispatches it as a batch step and reads the receipt; the commit happens in a following batch step. AC: reflect and the three skeptic lenses of one real lane run locally end to end and pass `assertReadWitness`; the lane's outcome equals the hosted run's on the same commit.
4. **Schema via forced tool.** `submit_answer` with the stage schema as parameters; `required` extended as in §6; `response_format` kept only as a probe.
