The Qwen3.5 repetition loop problem (infinite `!!!!!!!!` or circular reasoning in `&lt;think&gt;` blocks) has been documented in GitHub issues for the 3.6 series too (issues #88, #145 on QwenLM/Qwen3.6). The larger models (397B, 122B) are more affected. The 35B-A3B is **not specifically called out** in these issues, but the architectural family shares the risk.

### Q4 Quantization Tax
This is the biggest practical concern. From InsiderLLM's detailed analysis:

- **Standard Q4_K_M breaks agentic reliability**: tool-call JSON formatting errors, diff formatting problems, instruction drift in long loops. Chat works fine; the failure mode is specifically in multi-turn structured output under agentic load.
- **The fix**: Use **imatrix-calibrated Q4** (Unsloth's `UD-Q4_K_XL` or bartowski builds) instead of stock Q4_K_M. Same VRAM, meaningfully better weight protection for the critical layers.
- **Fallback**: If calibrated Q4 still drifts, step to Q5_K_M or Q6_K. On your 64GB machine, Q6_K fits at ~30GB, leaving plenty of room for context.

### Gated DeltaNet Runtime Support
The new attention architecture is not yet fully optimized everywhere:
- **MLX**: Works. MLX quants of both models run cleanly on Apple Silicon.
- **llama.cpp**: Needs build b8954+ for proper Gated DeltaNet kernels. Metal kernels lag behind CUDA. Early builds showed **~35% slower than Qwen3-30B-A3B** on the same hardware, though this is an implementation gap, not fundamental.
- **Ollama**: Since 0.19 (March 2026), Ollama uses MLX natively on Mac, so this path avoids the llama.cpp Metal issue entirely.
